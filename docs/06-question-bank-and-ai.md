# 06. 문제은행과 AI

## 1. 원칙

- AI가 만든 문항은 **검증 후** 공용 문제은행에 저장하고 같은 조건의 다른 학생에게 재사용 `[명세]`
- 출제는 DB 조회 + 배정 알고리즘이 기본 `[명세]`
- 학생 풀이 이력은 문항 원본과 분리 저장 `[명세]`
- 학생 요청 처리 경로에서 AI를 동기 호출하지 않음 (부족분은 `aiJobs`로 비동기 보충)

## 2. 문항 태그

| 구분 | 필드 |
|---|---|
| 필수 `[명세]` | 학년, 과목, 출판사/판본, 단원·소단원, 성취기준, 개념, 난이도(1~5), 유형, 정답·해설, 검증상태 |
| 선택 `[명세]` | 선수개념, 예상 풀이시간, 그래프/도형 유형, 변형문항 그룹, 중간·기말 범위 |

스키마는 [03-data-model](03-data-model.md) §2.5 참고.

## 3. 문항 유형 (단계별)

| 단계 | 유형 | 채점 |
|---|---|---|
| MVP | 객관식(`mcq`) | 선지 인덱스 일치 |
| MVP | 단답형(`short`) | 정규화 후 `answer` 또는 `acceptable[]` 일치 |
| 이후 | 서술형(`essay`) | ⚠️ 채점 기준 미정 (출시 전 필수 확인 항목) |

단답형 정규화 `[제안]`: 앞뒤 공백 제거, 전각→반각, 영문 소문자화, 숫자 표기 통일(`1/2` = `0.5`는 문항별 허용 목록으로만 처리, 자동 수학 동치 판정은 하지 않음).

## 4. 문항 생명주기

```
draft ──(자동 검증)──▶ auto_checked ──▶ needs_review ──(검수자 승인)──▶ verified
  ▲                        │ 실패                                         │
  └────── 재생성/수정 ◀────┘                          이의제기 인정·오류 ─▶ disabled
```

| 단계 | 처리 |
|---|---|
| 자동 검증 | ① JSON 스키마 검사 ② 객관식: 정답 선지 1개, 선지 중복 없음 ③ 시각자료: 좌표·정답 일치 검사(§6) ④ **별도 AI 호출로 독립 풀이 → 정답 일치 확인** ⑤ 유사 문항 검사 |
| 사람 검수 | MVP에서는 **모든 AI 문항을 사람이 승인 후 verified** `[제안]`. 품질 데이터가 쌓이면 자동 승인 비율 확대 |
| 운영 중 | 이의제기, 비활성화, 실제 정답률 기반 난이도 보정 `[명세]` |

### 4.1 난이도 보정 `[제안]`

노출 30회 이상 문항에 대해 실제 정답률로 `calibratedDifficulty` 계산.

| 정답률 | 보정 난이도 |
|---|---|
| ≥ 85% | 1 |
| 70~85% | 2 |
| 50~70% | 3 |
| 30~50% | 4 |
| < 30% | 5 |

원래 태그와 2단계 이상 차이 나면 검수 대기열로 보냅니다.

### 4.2 유사 문항·중복 방지

- 같은 `variantGroupId`는 같은 날 한 번만 배정
- 생성 시 같은 개념의 기존 문항 본문과 비교 (MVP: 정규화 텍스트 n-gram 유사도, 이후 임베딩 검토) `[제안]`

## 5. AI 작업 유형

| 작업 | 트리거 | 입력 (개인정보 없음) | 출력 |
|---|---|---|---|
| generate | 은행 부족, 어드민 요청 | 학년·과목·성취기준·개념·난이도·유형·예시 문항 | 문항 JSON N개 |
| variant | 복습용 변형 부족 | 원문항(정답 포함) | 변형 문항 JSON |
| verify | generate/variant 직후 | 문항(정답 제외) | 독립 풀이 답 |
| explain | 검수자 요청, 해설 품질 낮음 | 문항 + 정답 | 개선 해설 |
| analyze | 주간 리포트 | **익명화된** 집계 수치 | 짧은 해석 문장 |
| errorCause | 오답노트 (선택) | 문항, 학생 답안 | 원인 추정 (화면에 "추정" 표시) |

### 5.1 호출 구조

- Cloud Functions에서만 호출, API 키는 `defineSecret('ANTHROPIC_API_KEY')`
- 모든 출력은 **JSON 스키마로 강제**하고 파싱 실패 시 최대 2회 재시도 `[제안]`
- 모든 호출을 `aiUsageLogs`에 기록 (목적, 모델, 입력/출력 토큰, 성공 여부)
- 모델명은 `appConfig.ai.models.{generate|verify|analyze}`로 관리. ⚠️ 구체 모델명·단가는 [Anthropic 공식 문서](https://docs.claude.com)와 가격 페이지에서 확인 후 기입

### 5.2 생성 프롬프트 출력 스키마 (예)

```json
{
  "questions": [{
    "type": "mcq",
    "difficulty": 3,
    "stem": "다음 중 ...",
    "choices": ["...", "...", "...", "...", "..."],
    "answer": "2",
    "explanation": "...",
    "expectedSec": 60,
    "visual": null
  }]
}
```

## 6. 시각 자료 (수학 그래프·도형·좌표, 과학 실험 그림)

AI 이미지 생성이 아니라 **구조화 데이터 + 검증된 템플릿**을 SVG/Canvas로 렌더링합니다 `[명세]`.

```ts
type VisualSpec =
  | { kind: 'coordinate', xRange: [number, number], yRange: [number, number],
      points?: { label: string, x: number, y: number }[],
      functions?: { expr: string, domain?: [number, number] }[] }   // 예: "2*x+1"
  | { kind: 'geometry', template: 'triangle' | 'circle' | 'parallel-lines' | ...,
      params: Record<string, number>, labels: Record<string, string> }
  | { kind: 'experiment', template: string, params: Record<string, unknown> }
```

- 렌더러: `apps/web/src/components/visual/` (SVG, 다크 모드 대응 색상은 CSS 변수 사용)
- 수식 파서: 안전한 표현식 파서 사용 (예: mathjs의 `parse`/`evaluate`), `eval` 금지
- **자동 검사** `[명세]`: 문항의 정답이 좌표·값에 의존하면 렌더 데이터로 재계산해 정답과 일치하는지 확인 (예: "점 A의 좌표는?" → `points`에서 A 조회 후 비교)
- 템플릿 목록은 어드민에서 미리보기 가능

## 7. 교과서 목차 확보

- 공개 출판사 자료 등에서 목차 확보, 실패·불일치 시 관리자 수동 등록 `[명세]`
- 자동 수집 스크립트는 `functions/scripts/` 또는 별도 로컬 도구로, 결과는 `status: 'draft'`로 저장 후 관리자 승인
- ⚠️ 출판사 자료의 이용 조건(약관·저작권)은 출처별로 확인 필요. 문항 저작권·출처 관리 필요 `[명세 16장]`

## 8. AI 비용 산정

### 8.1 산식 `[명세]`

```
월 AI 비용(원) = Σ 모델별 [ 입력토큰 ÷ 1,000,000 × 입력단가($)
                           + 출력토큰 ÷ 1,000,000 × 출력단가($) ] × 환율
```

### 8.2 주의 사항 `[명세]`

- 학생당 월 1,500~3,000문제 **노출**은 AI 생성 수가 아님. 은행 적중률이 높으면 대부분 DB 조회
- 문제당 600 입력 / 450 출력 토큰은 **이전 대화의 임시 가정**이며 실측값이 아님
- 월 320원·1,400원·2,600원 등은 **검증되지 않은 참고치로 원가로 사용 금지**
- 서버·DB·스토리지·결제 수수료·고객지원 비용은 별도 계산

### 8.3 실측 절차

1. 동일한 **100문항 평가 셋**(과목·난이도 분포 고정) 준비
2. 후보 모델별로 generate + verify 실행, `aiUsageLogs`에서 토큰 합계 수집
3. 품질 지표: 자동 검증 통과율, 검수자 승인율, 수정 필요율
4. 공식 단가·환율 입력 → 어드민 비용 화면에서 문항당·학생당 원가 산출
5. 은행 적중률(배정 중 기존 문항 비율)을 함께 기록해 월 원가 추정
