# 개인 풀이 이력과 개념·유형별 적응 학습

2026-10-15 구현. 10문제는 일일 진도 학습 회차의 상한이며, 단원 완료를 뜻하지 않는다. 목차만 있는 교재에는 내용을 추측한 학습지도를 만들지 않는다. 본문이 등록되면 그 범위에서 지도와 필요한 문항을 준비한다.

## 기록과 출제 목적

- `daily`: 진도 학습. 같은 날의 배정을 재개하며 과목별 목표를 넘지 않는다.
- `extra`: 사용자가 선택한 단원의 새 문제. 확인을 마친 단원도 선택할 수 있다.
- `reinforce`: 복습일까지 기다리지 않는 취약 유형 보강. 아직 노출하지 않은 문항을 쓴다.
- `review`: 예정된 개념의 정기 복습. 새 변형을 우선한다. 새 변형이 없으면 이전 문항을 명시적으로 재사용하고 이유를 기록한다.
- `practice`: 사용자가 고른 같은 문제 다시 풀기. 기록은 남지만 숙련도·복습 일정·포인트는 바꾸지 않는다.
- `assessment`, `exam`: 학습한 개념을 새로운 문항으로 확인한다.

`students/{studentId}` 아래에 다음 정보를 분리한다. 기존 학생 접근 권한과 서버 전용 Firestore 정책을 그대로 사용한다.

| 컬렉션              | 목적                                                                                         |
| ------------------- | -------------------------------------------------------------------------------------------- |
| `questions`         | 개인 자료로 생성했거나 등록한 검증 문항. 개인 자료는 공용 은행으로 자동 공개하지 않는다.     |
| `assignments`       | 그날 배정한 문제의 원문·정답 스냅샷, 출제 목적, 문항별 선정 이유, 당시 교재·단원 이름과 버전 |
| `answerEvents`      | 답안 제출 즉시 보존하는 날짜별 이력. 이해도 미선택 상태와 이해도 저장 완료 상태를 구분한다.  |
| `attempts`          | 기존 호환용 이해도 저장 완료 기록. 오답 메모를 제외한 판정과 분기 스냅샷을 보존한다.         |
| `questionExposures` | 전체 기간의 개인별 문항 배정·열람·답안 제출 인덱스                                           |
| `unitPlans`         | 단원 본문 버전별 기대 개념·유형 목록                                                         |
| `skillProgress`     | 유형별 현재 상태·복습일·간격, 확인에 사용한 최근 증거, 최초 진도 확인 시점                   |

새 답안에는 선정 이유, 이전 풀이 ID, 복습일·간격·취약도·유형 상태의 변경 전후 값과 정책 버전을 기록한다. 보강의 연결 원인은 같은 개념의 다른 유형에서 마지막으로 푼 문제가 아니라 해당 취약 유형의 이전 기록을 우선한다. 정답과 해설을 공개하기 전에는 이해도를 제출할 수 없다.

정기 복습 일정도 유형별로 저장한다. 개념 목록에는 해당 유형들의 가장 이른 복습일을 보여주며, 다른 유형의 정답 때문에 취약 유형의 복습일이 늦춰지지 않는다. 예정된 유형마다 새 문항을 우선 배정하고, 없으면 해당 유형에서 풀었던 문항을 명시적으로 재사용한다. 이력의 복습일 변경 전후 값은 당시 답한 유형의 일정이다.

## 중복 방지와 이전 기록

문항 ID와 별도로 정규화한 문제 본문 및 보기 집합의 SHA-256 지문을 사용한다. 공백·유니코드 표기·보기 순서를 바꾸거나 새 ID를 붙여도 같은 문항을 새 문제로 처리하지 않는다. 숫자나 연산자가 달라지는 정당한 변형은 별도 문항이다. 일반 학습·추가 문제·보강·평가에는 30일 만료 규칙을 적용하지 않는다. 의미적으로 같은 모든 자연어 표현을 완벽히 판별한다는 보장은 하지 않으며, 생성 단계의 중복 검토도 함께 사용한다.

배정 트랜잭션에서 일일 한도와 문항 지문을 다시 읽고 예약을 함께 저장한다. 다른 창이나 다른 학습 종류에서 동시 요청해도 같은 문항을 새 문제로 중복 배정하지 않는다. 추가 문제와 보강은 요청 ID로 재시도를 식별한다. 기존 회차 재개를 위해 추가 AI 출제를 불필요하게 실행하지 않는다.

이전 `assignments`와 `attempts`는 페이지 단위로 읽어 인덱스와 이력 화면용 기록을 추가한다. 원본 기록은 수정하지 않는다. 배정·열람을 보수적으로 노출 이력에 포함하며, 예전 답안에 없는 선정 이유나 분기 경로를 소급해서 만들어내지 않는다. 답안 공개 후 이해도를 선택하지 않은 기록도 별도 표시한다. 대량의 이전 기록은 저장한 커서부터 이어 처리하며, 처리가 끝나기 전에는 불완전한 인덱스로 새 문제를 배정하지 않는다.

## 단원 확인 기준과 필요한 문항 수

운영 정책 `adaptive-v1`의 초기값은 다음과 같다. 교육학적으로 검증된 최적 수치나 성적 보장 기준이 아니며, 정책 변경 시 버전과 회귀 검증을 함께 관리한다.

1. 유형마다 서로 다른 문항 3개 이상을 확인한다.
2. 최근 확인 문항 2개는 정답이며 해설 후 이해도가 ‘알겠어요’여야 한다.
3. 두 확인 문항은 서로 다른 날짜의 기록이어야 한다.
4. 같은 문항의 성공적인 반복은 새 변형이나 다른 날의 확인을 대신하지 않는다. 반복 문항에서 다시 틀리거나 헷갈리면 현재 취약 상태에는 반영한다.
5. 모든 기대 유형에서 최초 확인을 마쳐야 다음 단원으로 이동한다. 일부 문항이 존재한다는 이유만으로 해당 단원의 전체 유형을 확인했다고 추정하지 않는다.

최초 진도 확인 시점과 현재 취약 상태를 분리한다. 과거에 확인한 유형이 나중에 취약해져도 이미 진행한 교육과정 전체를 되돌리지 않고 보강과 정기 복습 대상으로 관리한다. 의사결정에는 최근 16개의 확인 증거를 보관하며, 전체 풀이 기록은 별도 이력으로 계속 남긴다.

문제은행의 초기 준비 목표는 유형당 4문항이다. 실제 AI 요청은 부족한 유형을 번갈아 최대 8문항씩 준비한다. 등록한 유형 수·기존 미노출 문항·현재 확인 상태에 따라 추가 생성량이 달라진다. 학습자가 초기 준비 물량 전체를 반드시 풀어야 한다는 의미는 아니다. 이미 충분한 새 문항이 있으면 추가 생성하지 않는다. 실제 배정은 검증 문항과 확인할 유형이 부족하면 10문항보다 적을 수 있다.

본문 버전은 단원별로 관리한다. 다른 단원의 본문을 추가하거나 수정해도 그대로인 단원의 지도와 확인 기록을 무효화하지 않는다. 해당 단원의 본문·핵심개념이나 교재의 학교급·학년·과목이 바뀌면 그 단원의 새 버전을 사용한다. 옛 문제와 풀이 이력은 그대로 남는다.

## 화면과 API

- `나의 교재 → 개념·유형 학습지도`: 본문 기준의 기대 유형, 현재 상태, 진도 확인 수, 추가 문제·보강·지도 편집.
- `복습`: 정기 복습과 지금 시작할 취약 유형 보강을 분리한다.
- `풀이 기록`: 한국 시간의 날짜·학습 종류·교재로 조회하고 답안·해설·이해도·분기 변경 전후 및 연결된 이전 풀이를 확인한다.
- `GET /api/history`: `date`, `mode`, `bookId`, `cursor`로 페이지 조회. `attemptId`로 현재 학습자에게 속한 연결 기록 하나를 읽을 수 있다.
- `POST /api/adaptive`: 현재 교재 버전과 개념·유형 목록을 검증해 개인 학습지도를 저장한다.
- `POST /api/learn`: 기존 답안·이해도 2단계 저장과 더불어 `extra`, `reinforce`, 요청 ID, 단원·유형 선택을 지원한다.

AI는 기존 Responses API의 [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)를 사용한다. 지도에는 본문 인용 근거를 검증하고, 생성 문항은 지정한 개념·유형과 본문 근거를 확인한 뒤 독립 풀이 검증을 거친다. 기존 문항이 있는 단원은 개념 이름을 유지해 이전 기록과 연결한다. 검증에 실패한 문항은 검수 대기로 남긴다.

## 검증

- 순수 함수 회귀 테스트: 서로 다른 날짜·문항의 숙련도, 취약 유형의 원인 연결, 기대 유형 누락, 숫자 변형, 단원별 버전, 지도의 부족 문항 계산.
- `node scripts/verify-adaptive-learning.cjs --live`: 임시 Firebase 학습자에서 이전 이력 페이지 처리, 이해도 미선택 답안, 30일 이전 중복 차단, 동시 배정, 보강과 복습의 분리, 수동 재풀이, 진도 이동과 버전을 확인한다.
- 같은 명령에 `--with-ai`: 자체 합성 본문으로 실제 지도 분석·유형별 출제·독립 정답 검증을 실행한다. 실제 학생의 자료나 진도를 테스트 값으로 덮어쓰지 않으며 임시 데이터는 정리한다.
- 기존 서버 학습 통합 검증과 빌드를 함께 수행한다.
