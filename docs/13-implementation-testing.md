# 현재 구현·테스트 안내

기준: 2026-10-15. B 디자인의 로그인 학습 기능을 테스트하기 위한 안내입니다.

## 바로 테스트하는 순서

1. Chrome에서 `http://127.0.0.1:3000/b`를 엽니다. `localhost`와 `127.0.0.1`의 로그인 쿠키는 서로 다르므로 같은 주소를 사용합니다.
2. 보호자 메뉴에서 학습 프로필을 선택합니다. 개발 검증에 사용한 별도 프로필은 `기능 테스트`이며 기존 프로필을 변경하지 않았습니다.
3. 나의 교재 → 교재 찾기에서 교재명/저자/출판사로 검색하거나 표지 사진을 올립니다. 출판사·저자·개정판을 확인하고 목차를 불러와 시작·종료 단원을 선택합니다. 공식 카탈로그는 Firebase 28종·183개 대단원입니다. 사용자에게 목차 업로드를 요구하지 않습니다.
4. 수업 필기·본문은 학습 자료 올리기 또는 등록 교재의 단원별 본문 인식으로 추가합니다. 파일은 5MB 이하 PNG/JPEG/WebP/PDF/TXT, 직접 붙여넣기는 30,000자까지입니다. 교재 전체 본문은 10만 자, 단원별 24,000자 제한입니다. 목차 연결만으로 본문이 생성되지는 않습니다.
5. 단원 출제를 시작하고 검증 통과 문항 수를 확인합니다. 작업 상태는 6초마다 갱신됩니다. 재시도는 최대 3회입니다.
6. 학습하기 → 답안 제출 → 정답·해설 확인 → 3단계 이해도 선택·저장 → 다음 문제. 이해도 선택 전에는 학습 완료·포인트·복습 일정을 반영하지 않습니다. 제출한 답안과 풀이 시간은 정답 공개 시 서버에 고정하며, 같은 날 닫았다 다시 열어도 정답·해설 화면부터 이어갑니다.
7. 오답노트의 메모를 저장하고 새로고침하여 확인합니다. 재풀이는 포인트와 복습 일정을 바꾸지 않습니다.
8. 학습 리포트에서 최근 7일 집계와 저장한 주간 리포트를 확인합니다. 인쇄 대화상자에서 PDF로 저장할 수 있습니다.
9. 관리자에서 학습 프로필을 고르면 AI 생성 문항·검수 상태·작업 내역을 볼 수 있습니다. 해당 관리 조회는 감사 로그에 남습니다.

검증된 문항이 적으면 목표 수보다 적게 배정할 수 있습니다. 완료한 일일 배정은 그날 추가 출제해도 자동으로 확장되지 않습니다. 새 문항은 다음 배정에서 사용합니다. 새 문제 한도는 같은 과목의 여러 교재를 합산합니다.

## 학생 계정 연결

보호자 메뉴에서 학생 Google 이메일을 지정하고 24시간 코드를 발급합니다. 학생은 해당 이메일로 로그인한 후 프로필 생성 화면에서 코드를 입력합니다. 보호자가 연결 요청의 이메일을 확인하고 승인해야 접근이 열립니다. 학생 계정은 연결된 학습 프로필만 접근하며 결제·가족 프로필 변경은 제한됩니다. 해제해도 학습 기록은 보호자 프로필에 남습니다. 초대 코드 자체는 해시로 보관합니다.

## 검증 결과

- 단위 테스트 39개: 입력 검증, 권한 필드 주입 차단, CSRF, 복습·난이도·보상, 단답형 정규화, 목차 진도, 과목별 한도, 중복 문항, 출처 URL, 번역 변수 보존, 교과서 저자/개정판/학기 오매칭 차단, 사회 권/학년 구분, DB 카탈로그 우선 적용.
- 실제 Firestore/OpenAI 통합 16개: 다른 보호자 접근 차단, 동시 배정/채점 멱등성, 포인트 중복 방지, 실제 텍스트 인식, 객관식·단답형 생성과 독립 검증, 교재별 배정, 구독 상태 중복 이벤트, 이메일 지정/보호자 승인/학생 권한 분리.
- 실제 이미지 업로드와 PDF 입력으로 본문 추출을 확인했습니다. 이미지 테스트는 7문항 승인·1문항 검수 대기, 추가 혼합형 테스트는 8문항 승인됐습니다.
- 이해도 순서 변경 후 Firestore 학습 통합 10개 재검증: 답안 공개 전 이해도 저장 차단, 제출 답안·시간 고정, 정답 공개 후 재개, 이해도 저장 시 단일 보상, 다른 계정 접근 차단. `node scripts/verify-integrations.cjs --live --learning-only`로 AI 호출 없이 실행합니다.
- TypeScript 검사와 Next.js production build 통과.
- 교재 매칭 통합 4개: 실제 Firebase 목록 조회·중복 제거, 단원 범위 등록, 재등록 시 본문·범위 보존, 실제 AI 식별→카탈로그 매칭. `node scripts/verify-textbook-matching.cjs --live --with-ai`로 임시 자료만 사용해 재검증합니다.
- 공개 배포의 실제 Chrome에서 공식 미래엔 수학1 표지 이미지 → 미래엔/황선욱/중1 후보 1종 → 등록된 8개 단원 불러오기를 확인했습니다. 표지에 없는 교육과정은 추정하지 않고 판본 확인 안내를 표시했습니다.
- 실제 카드 등록/PG 승인은 미검증입니다.

## 관리자와 운영 범위

관리자는 공유 교재·문제은행과 개인 문제은행을 구분해 관리합니다. 개인 교재/학습 기록은 owner/admin만 조회할 수 있고 editor/reviewer는 접근할 수 없습니다. JSON 편집·가져오기/내보내기를 제공하며, 출처와 성취기준은 운영자가 검증해 입력합니다. 문항별 `approved`, `pending`, `disabled` 상태가 있으며 AI 재검증만으로 오류가 완전히 제거되는 것은 아닙니다.

통계는 실제 수집된 기록을 집계하며 표본이 5개 미만이면 추세 판단을 유보합니다. 수동 저장/정기 작업이 주간 보고서를 생성합니다. 이메일/SMS 전송은 하지 않습니다. 결제 이력이 있는 계정의 삭제 요청은 보존 범위 검토 대기열로 접수되며, 관리자 메모만으로 실제 삭제가 완료되지는 않습니다.

최초 설계의 전용 그림 편집기, 전체 교육과정·출판사 데이터베이스, 대규모 KPI·A/B 평가 시스템, 다국어 법적 문서, 학생 모드 PIN 잠금은 현재 테스트 범위에 포함되지 않습니다. 로그인 학습의 자료 인식→목차 확인→출제→채점→복습→리포트 흐름과 분리된 확장 항목입니다.

## 보안·외부 연결

원본 이미지/PDF를 서버에 장기 보관하지 않습니다. 사용자 확인을 거친 추출 텍스트와 문항은 개인 학습 프로필에 저장합니다. 업로드 내용은 AI 요청의 비신뢰 데이터로 처리하며 개인정보를 추출하지 않도록 지시합니다. 서버 저장 여부와 무관하게 필요한 자료만 업로드해야 합니다.

토스 키와 암호화 키 없이 구독 버튼은 실제 결제를 실행하지 않습니다. 테스트 설정은 `TOSS_MODE=test`, 실결제 활성화는 `TOSS_MODE=live`와 `ENABLE_LIVE_BILLING=true`를 함께 요구합니다. 결제 결과는 클라이언트 입력만으로 인정하지 않으며 Toss 서버 조회/승인 응답의 주문·금액·통화를 확인합니다. 이미 취소된 주문에 늦게 도착한 완료 이벤트가 권한을 다시 열지 않습니다.
