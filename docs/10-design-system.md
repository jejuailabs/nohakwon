# 10. 디자인 시스템 (시안 v1 기준)

> **디자인 방향 확정 (2026.10.14):** 사용자가 B · 캐릭터 퀘스트를 선택했습니다. 기본 진입 화면은 `/b`이며, 이후 개발은 이 문서의 게임형 다크 UI 방향을 따릅니다. A · 학습 마을은 이전 시안으로 보존합니다.

- 기준 시안: `designs/mockup-v1.png` (데스크톱 + 모바일 합성 이미지 1장, 2026.10.14 수령)
- 문서 상태: **초안** — 시안 이미지 해상도가 낮아 작은 글씨·정확한 색상값은 판독이 어렵습니다. 판독이 불확실한 부분은 `(판독 불확실)`, 이미지에서 눈대중으로 뽑은 값은 `[추정]`으로 표시했습니다. **원본 디자인 파일(Figma 등)을 받으면 이 문서의 값을 교체**해야 합니다.

> 시안 원본 이미지는 저장소 `designs/mockup-v1.png`에 넣어 두고 이 문서에서 참조합니다.

## 1. 디자인 콘셉트

| 항목 | 시안에서 읽히는 방향 |
|---|---|
| 장르 | **게임형 학습 대시보드** (RPG·수집형 게임 UI 문법) |
| 분위기 | 짙은 남색·보라 배경의 판타지 야간 무드, 네온 글로우, 금색 포인트 |
| 핵심 메타포 | 과목 = 캐릭터, 학습 = 퀘스트, 포인트 = 재화, 레벨·경험치 |
| 일러스트 | 애니메이션풍 과목별 캐릭터 5종 + 검은 고양이 마스코트 |
| 카피 톤 | 붓글씨풍 손글씨 슬로건 ("지식을 모아 더 강한 나로!", "오늘도 좋은 선택이야!") |

### 1.1 명세서와 맞춰야 할 원칙

명세서 12장(문제 영역은 가독성 우선, 장식은 주변 UI)과 문서 05 §3.6(솔직함 보상)을 기준으로 시안을 해석합니다.

1. **문제 풀이 카드 내부에는 장식을 넣지 않습니다.** 캐릭터·글로우는 카드 바깥에만 둡니다.
2. **자기평가 3버튼이 시안에 없습니다.** 문제 카드에 반드시 추가해야 하며, 세 버튼은 같은 크기·같은 시각적 무게로 둡니다 (§5.3).
3. 게임 요소는 **저자극 모드**에서 꺼질 수 있어야 합니다 (§9).

| 요소 | 시안 내용 | 구현 메모 |

#### 2.1 탭 매핑 제안 `[제안]`

시안의 게임형 탭 이름과 명세서 기능을 연결합니다. 탭 라벨은 시안 원본 확인 후 확정합니다.

| 순서 | 시안 성격 | 연결할 기능 (문서) |
|---|---|---|
| 1 | 홈 | 오늘의 학습 (05) |
| 2 | 퀘스트 계열 (판독 불확실) | 예정 복습·주간 시험 (05, 09) |
| 3 | 캐릭터 | 캐릭터·테마 꾸미기 (07 §3) |
| 4 | 도감 | **오답노트·개념 정복 현황** — "모르던 개념을 정복해 도감을 채운다" 구조로 연결 권장 |
| 5 | 상점 계열 (판독 불확실) | 포인트로 꾸미기 아이템 해금 (05 §3.6.5) |

### B. 히어로

- 좌측: 붓글씨풍 슬로건 + 작은 설명 2줄 (판독 불확실)
- 중앙: **과목 캐릭터 카드 5장** — 각 카드 하단에 과목명(국어·영어·수학·사회·과학)과 한 줄 부제(판독 불확실)
- 우측: 말풍선 "오늘도 좋은 선택이야!" + 검은 고양이 마스코트
- 카드 클릭 → 해당 과목 문제 풀이로 이동 `[제안]`
- 모바일에서는 캐릭터 1~2장만 보이는 축소 배너로 변경 (§4)

### C. 오늘의 50문제

- 제목 "오늘의 **50**문제" (숫자 강조), 날짜 표시
- 우측 상단 작은 버튼 (판독 불확실, "도전 과제 보기" 류로 보임)
- **과목별 원형 진행 링 5개**, 각 링 아래 과목명과 "10/10"
- 링 색은 과목 색(§3.3)
- 수량은 고정 50이 아니라 `dailyAssignments.counts`에서 표시 (과목 끄기·학습량 변경 반영). 복습이 있으면 "+ 복습 N" 보조 표기 `[제안]`

### D. 지금 도전 중 (문제 카드)

- 헤더: "지금 도전 중 · 수학" + 진행 "3/10" 류 표기 (판독 불확실)
- 좌측: 과목 캐릭터 일러스트 + 말풍선 (판독 불확실)
- 우측: 문제 본문 + **선지 2×2 그리드**, 선택된 선지는 보라색 강조, 하단 "다음 문제" 버튼
- 좌하단 작은 버튼 (판독 불확실, 힌트 류로 보임)

> ⚠️ 시안 속 예시 문제 "12 + 3 × 2의 값은?"의 보기(6, 8, 12, 24로 보임)에는 정답 18이 없습니다. 시안용 더미 텍스트로 보이며, 구현 시 실제 문항 데이터를 써야 합니다. 마케팅 이미지에 그대로 쓰지 않도록 주의하세요.

**시안에 추가해야 할 것 (필수):**

1. 답 선택 후 → **자기평가 3버튼** → 정오·해설 공개 순서 (문서 01 §5)
2. 솔직함 포인트 `+N` 피드백 (문서 07 §3.1)
3. 해설 영역, 이의제기(신고) 버튼
4. 단답형 입력 UI, 그래프·도형 시각자료 영역 (문서 06 §6)

### E. 나의 정보

- 아바타 + 닉네임 + "Lv.28"
- 경험치 바 "1,240 / 2,000"
- 하단 아이콘 3종 + 수치 (불꽃·번개·보석 계열로 보임) → §6 재화 매핑 참고
- 우측 상단 작은 링크 (판독 불확실)

### F. 나의 파티

- 제목 "나의 파티" + 부제 (판독 불확실), 우측 "더 보기" 류 버튼
- 캐릭터 카드 5장, 각 카드에 Lv 표기와 별점(★)
- 연결 제안: 과목별 캐릭터 레벨 = **해당 과목 숙련도 요약**. 별 = 과목 내 정복 개념 비율 구간 `[제안]`

### G. 진행 중 퀘스트

- 아이콘 + 퀘스트명 + 진행 수치 3줄 (판독 불확실)
- 연결 제안: "오늘의 복습 완료", "모르겠다 개념 1개 극복하기", "7일 연속 학습" 등 — 솔직함·극복 행동을 퀘스트로 노출 `[제안]`

### H. 최근 획득 아이템

- 아이템 아이콘 그리드 (보석·책·상자 류로 보임)
- 연결: 포인트로 해금한 꾸미기 아이템, 획득 배지

### I. 오늘의 보상

- **원형 룰렛** + 우측 보상 목록 + 하단 버튼
- ⚠️ 미성년자 대상 확률형 보상 이슈 → §8에서 대체안 제시

## 3. 디자인 토큰

> 아래 HEX는 압축 이미지에서 눈으로 뽑은 **추정값**입니다. 원본 파일 수령 후 교체하세요. 토큰 이름은 문서 07 §2.3과 같은 체계를 씁니다.

### 3.1 다크 테마 (시안 기본) `[추정]`

| 토큰 | 값 `[추정]` | 용도 |
|---|---|---|
| `--color-bg` | `#0B1030` | 페이지 배경 (짙은 남색) |
| `--color-bg-gradient` | `#0B1030 → #1A1450` | 상단 히어로 영역 그라데이션 |
| `--color-surface` | `#141A40` (투명도 85%) | 카드 배경 |
| `--color-surface-raised` | `#1E2458` | 선지·내부 박스 |
| `--color-border` | `#3A3F8F` (투명도 60%) | 카드 테두리 |
| `--color-glow` | `#6C5CFF` | 카드 외곽 글로우 |
| `--color-text` | `#F2F4FF` | 본문 |

### 3.2 라이트 테마 ⚠️ 시안 없음

시안은 다크 모드만 있습니다. 요구사항(다크/라이트 토글)을 맞추려면 라이트 시안이 필요합니다. 받기 전까지의 임시 원칙 `[제안]`:

- 배경 `#F5F6FF`, 카드 `#FFFFFF`, 본문 `#1A1D3A`, 테두리 `#DADDF5`
- 글로우는 그림자(`0 4px 16px rgba(60,50,180,.12)`)로 대체
- 주요색·과목색·금색 포인트는 유지하되 흰 배경 대비(WCAG AA) 재검증
- 캐릭터 일러스트는 공통 사용, 히어로 배경 이미지는 라이트용 별도 필요

| 과목 | 토큰 | 값 `[추정]` |

| 국어 | `--subject-kor` | `#FF5A6E` (붉은 계열) |
| 영어 | `--subject-eng` | `#4D8BFF` (파랑 계열) |

### 3.4 자기평가·채점 색 `[제안]` (시안에 없음)

| 토큰 | 다크 | 의미 |
|---|---|---|

자기평가 3버튼은 **배경색 강도를 같게** 하고 색은 테두리·아이콘에만 씁니다. "알았다"만 눈에 띄면 솔직한 선택이 줄어듭니다.

## 6. 게임 요소 ↔ 학습 데이터 매핑

시안에는 레벨·경험치·보석·코인·에너지 등 재화처럼 보이는 요소가 여러 개 있습니다. 재화가 많으면 학생도 헷갈리고 구현도 복잡해지므로 아래처럼 정리하는 것을 제안합니다 `[제안]`.

| 시안 요소 | 연결할 데이터 | 비고 |
|---|---|---|
| 레벨 / 경험치 바 | `points.lifetime` 누적 기반 레벨 | 사용해도 줄지 않음 (성장 지표) |
| 보석 (또는 코인) | `points.balance` — **사용 가능한 포인트 1종으로 통일** | 문서 05 §3.6 솔직함 포인트 |
| 불꽃 아이콘 | `streak.current` 연속 학습일 | |
| 번개·"3/5" 류 | 오늘 학습 진행 (완료 과목 수 / 활성 과목 수) | 시안 의미 판독 불확실 ⚠️ |
| 캐릭터 레벨·별 | 과목별 숙련도 요약 (`conceptMastery` 집계) | |
| 도감 | 정복한 개념 목록 | |
| 퀘스트 | 일일·주간 목표 (복습 완료, 극복, 연속 학습) | |

> **에너지(횟수 제한)처럼 학습을 막는 장치는 쓰지 않습니다.** 학습량 상한은 "하루 최대 100문제" 규칙으로만 관리합니다.

## 8. ⚠️ "오늘의 보상" 룰렛 — 대체 제안

시안의 원형 룰렛은 확률형 보상(가챠)으로 읽힐 수 있습니다. 대상이 중학생이고 보호자가 결제하는 서비스이므로 다음 이유로 대체를 권장합니다.

- 결과가 운에 좌우되면 "공부한 만큼 받는다"는 솔직함 보상 원칙(문서 05 §3.6)이 흐려짐
- 학부모 신뢰·앱 마켓 심사 측면에서 확률형 요소는 설명 부담이 생김 (구체 규제 적용 여부는 확실하지 않음 — 법률 검토 시 함께 확인)

**대체안 `[제안]`:**

| 안 | 설명 |
|---|---|
| A. 확정 보상 상자 | 오늘의 학습을 끝내면 상자 열기 연출 → **정해진 보상**(포인트 + 오늘 극복한 개념 수 비례 보너스) |
| B. 보상 트랙 | 7칸 트랙, 학습 완료일마다 한 칸 전진, 정해진 칸에서 아이템 해금 (7일 체험 흐름과도 맞음) |
| C. 룰렛 유지 시 | 돈·포인트 구매로 돌릴 수 없게, 모든 칸이 꾸미기 아이템이며 **꽝 없음**, 확률 공개 |

시안의 원형 비주얼은 A·B 연출에도 재활용할 수 있습니다.

## 9. 접근성·저자극 모드

시안은 글로우·그라데이션·캐릭터가 많아 자극이 강한 편입니다.

| 항목 | 기준 |
|---|---|
| 대비 | 본문 텍스트 4.5:1 이상, 큰 글씨·아이콘 3:1 이상 (WCAG 2.1 AA). 시안의 작은 보조 텍스트(`--color-text-muted`)는 대비가 부족해 보임 → 원본 값으로 재측정 필요 |
| 글자 크기 | `--font-scale` 0.9 / 1 / 1.15 / 1.3, 레이아웃이 깨지지 않을 것 |
| 저자극 모드 (`data-low-stimulus`) | 글로우·블러·배경 일러스트 끔, 캐릭터는 작은 아이콘으로, 애니메이션 없음, 과목색 채도 낮춤 |
| `prefers-reduced-motion` | 포인트·레벨업 애니메이션 자동 축소 |
| 키보드 | 선지 1~4, 자기평가 Q/W/E 단축키 `[제안]`, 포커스 링 `--color-focus-ring` 명확히 |
| 색 의존 금지 | 정오·과목·자기평가 모두 아이콘/텍스트 병행 |
