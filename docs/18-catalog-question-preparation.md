# 공용 첫 학습 문제와 다음 단원 자동 준비

2026-10-20. 전체 출판사의 교재 첫 단원을 미리 준비하고, 학습 진입 시 바로 다음 단원을 준비한다.

## 학습 흐름

1. 공개된 모든 교재의 첫 단원을 `catalogPools`에 등록한다. 초등 4·5·6과 중1·2·3을 포함하며, 학년 선택이 가능한 교재는 선택 가능한 학년별로 준비한다. 임의로 일부 출판사를 생략하지 않는다.
2. 단원마다 독립 정답·근거 검증을 통과한 공용 문제를 최소 10개 저장한다. 미검증 문항은 문제은행에 검수 대기로 보관하되 학습자에게 전달하지 않는다. 준비 완료는 승인 문항 10개 이상일 때만 표시한다.
3. 교재 등록과 학습 시작에서 공용 문제와 개념·유형 지도를 학습자에게 복사한다. 첫 준비가 끝난 교재는 학습자마다 AI를 다시 호출하지 않고 바로 문제를 배정한다.
4. 실제 학습 회차를 시작하면 해당 교재의 다음 단원 하나를 준비한다. 범위 선택, 숙달, 진도, 포인트, 복습 일자는 바꾸지 않는다. 다음 단원에서 또 진입해야 그다음 단원이 준비된다.
5. 학습자가 이미 본 문제를 제외하고 새 문항이 부족하면 공용 문항을 보충한다. 같은 요청 ID의 보충은 한 번만 수행하고 공용 재고 상한은 단원별 160개다. 개인이 편집한 학습지도·본문과 취약 유형 보강은 기존 개인 출제 경로를 유지한다.

## 서버와 저장 경계

- 풀 식별자는 카탈로그 ID, 학교급·학년, 과목, 출판사·저자·개정·권, 교재·단원 리비전, 단원 제목·내용으로 나눈다. 다른 학년이나 바뀐 목차의 문제를 섞지 않는다.
- 공용 워커는 서버의 공개 카탈로그만 읽는다. 학습자가 올린 비공개 본문, 편집한 핵심개념은 공용 문제은행의 입력으로 사용하지 않는다.
- `questionBank`: 공용 승인/대기 문항. `catalogPools`: 진행 단계·검증 자료·유형 지도·작업 잠금·수량. `catalogDemands`: 중복 보충 방지 영수증. `operations/catalogWorkerSlots`: 최대 4개 동시 AI 작업.
- 학습자별 `questions`와 `unitPlans`에는 검증한 사본만 저장한다. `questionExposures`, `assignments`, `answerEvents`, `attempts`, `skillProgress`, 복습·포인트는 계속 개인별로 분리한다. 기존 출제·회차 예약의 중복 방지 규칙을 사용한다.
- 기존에 개인화·수정한 유형 지도를 공용 지도로 덮어쓰지 않는다. 공용 준비는 개인 진도나 답안을 생성하지 않는다.
- 교과서 본문이 없으면 공식 공개 자료로 확인한 공통 개념과 자체 예문만 사용하며 해당 표시와 출처를 유지한다. 실제 작품·지문 독해를 원하면 본문이 필요하다. 출처를 확인하지 못하면 `blocked`로 표시하고 사유를 운영 화면에 남긴다.
- 학습지도와 문항의 근거 인용은 [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)의 enum으로 실제 원문 발췌 중에서만 선택한다. 원문 문장을 바꿔 적어 반복 탈락하는 것을 방지하며, 인용 대조와 독립 정답 검증은 그대로 유지한다.
- 비상 수학1(이진호, 2022)의 다음 단원 범위는 [공식 비바샘 세부 목차](https://v.vivasam.com/educourse/index.do?lnbCode=106424&textbookCd=106424)를 직접 대조해 사전 등록했다. 저자·개정·학년·단원명이 맞는 경우에만 이 범위를 사용하며 자체 개념 설명을 생성한 뒤 별도 검증한다.

## 내구성 작업 큐

[Vercel Queues 공식 가이드](https://vercel.com/docs/queues/quickstart)와 [SDK 문서](https://vercel.com/docs/queues/sdk)를 사용한다. 큐 메시지는 풀 ID와 단계 번호만 담고 개인 자료나 키를 담지 않는다. `vercel.json`의 비공개 소비자가 서버에서 실행하며 브라우저가 닫혀도 계속된다. 배포 환경의 OIDC 인증을 사용하므로 별도의 외부 큐 계정·비밀키가 필요하지 않다.

단원 범위 확인 → 유형 지도 → 문항 생성·독립 검증을 각각 다른 큐 전달로 실행한다. 완료한 단계를 Firestore에 먼저 기록한 뒤 다음 단계를 발행한다. 함수가 중단되면 큐가 재전달하고 만료된 임대 이후 재개한다. 임대 토큰으로 늦게 끝난 옛 작업의 저장을 차단한다. 재전달·서버 동시 요청으로 같은 단계가 동시에 실행되지 않는다.

첫 준비나 보충은 최대 6묶음까지 생성한다. 일시 오류는 지수 간격으로 최대 3회 재시도한다. 개념 설명의 정확성 검토에서 지적을 받으면 사유를 반영해 새 자료를 작성·검증하고, 3회 실패하면 중단한다. 공개 출처로 범위를 확인하지 못한 자료는 즉시 중단한다. 서비스 전용 AI 일일 호출 한도는 4,000회이며 개인 한도와 분리한다. 완료/차단된 풀은 다음 대기 교재에 파이프라인을 넘긴다. 발행 실패나 새 교재는 기존 일일 유지 작업 또는 운영 화면의 ‘중단 작업 재개’에서 회복한다. 공용 자동 생성에는 결제를 실행하는 기능이 없다.

## 운영과 검증

관리자 → 운영 → **첫 학습 문제 준비**에서 전체·준비 중·완료·확인 필요 상태, 검증 문항 수와 실패 사유를 볼 수 있다. ‘전체 교재 첫 단원 준비’는 중복 생성 없이 새 범위를 등록한다. 차단된 자료는 확인 후 ‘다시 준비’로 명시적으로 재시도한다.

`node scripts/prepare-catalog.cjs --apply`: 모든 첫 단원 범위를 등록하고 상태를 `.local/catalog-preparation-status.json`에 저장한다. `--apply --work --max-steps=N`은 큐 외부의 관리용 워커로 동일한 체크포인트를 처리한다. 인자 없이 실행하면 읽기 전용 상태 조회다.

`node scripts/verify-catalog-preparation.cjs --live`: 폐기용 데이터로 동시 등록·작업 임대·단계 재개·10문항 보충·학습자 간 공유/개인 중복 방지·한 단원 앞 준비·실패 및 늦은 작업 차단을 검증한다. `--with-ai`는 실제 공식 교재 첫 단원을 채우고 즉시 학습 및 다음 단원 출제까지 확인한다. 실제 공용 검증 문항은 남기고 테스트 학습자와 임시 문항은 정리한다.
