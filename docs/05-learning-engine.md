# 05. 학습 엔진

모든 로직은 `packages/core`에 순수 함수로 구현하고, 수치는 `appConfig/main`에서 읽습니다.

> **표기 규칙:** `[명세]` = 명세서에 명시된 값, `[제안]` = 명세서에 없어 이 문서가 제안하는 초기값(운영 데이터로 조정 필요).

## 1. 교과서 목차·진도 엔진

### 1.1 구조

```
교육과정 성취기준 (공통 축)
   └─ 개념 concepts
        ↑ 매핑
출판사 × 학년 × 과목 × 판본 → 교과서 목차 units (대단원/소단원)
```

- 목차는 공개 출판사 자료 등에서 확보하고, 자동 수집 실패·판본 불일치 시 관리자가 확인·수동 등록 `[명세]`
- 교과서 본문 수집은 하지 않음 `[명세]`
- 교육과정 개정·판본 변경 시 `mappingVersion` 증가, 기존 학생은 이전 버전 유지 후 관리자가 이관 `[명세 16장]`

### 1.2 진도 포인터

- 학생·학부모가 과목별 현재 단원 선택 → `subjects[s].currentUnitId` `[명세]`
- 시스템은 선택 단원부터 목차 순서대로 진행 `[명세]`
- 단원 내 모든 개념의 신규 문항을 일정 수 이상 풀면 다음 단원으로 이동 `[제안: 개념당 최소 3문항]`
- 학생·학부모는 언제든 단원을 수동 조정 가능 (학교 진도와 맞추기)
- **이전 단원 진단** `[명세: 필요 시]`: 시작 단원이 1단원이 아니면 직전 단원 핵심 개념 5문항 진단 제안 `[제안]`. 오답 개념은 선수개념 복습으로 대기열 등록

## 2. 일일 배정 알고리즘 `buildDailyAssignment()`

### 2.1 수량 규칙

| 항목 | 값 |
|---|---|
| 신규 | 과목별 `dailyNew` (기본 10) × 활성 과목 수 = 기본 50 `[명세]` |
| 최대 | 신규 + 복습 ≤ 100 `[명세]` |
| 복습 슬롯 | 100 − 신규 수 |
| 초과 복습 | 다음 날로 이월 (`carriedOver += 1`) `[명세]` |

### 2.2 신규 문항 선택

```
for subject in 활성 과목:
  concepts = 현재 단원(→ 필요 시 다음 단원)의 개념 목록 (목차 순)
  for 슬롯 in 1..dailyNew:
    concept = 아직 충분히 다루지 않은 개념 중 목차 순 첫 번째
    target  = conceptMastery[concept].currentDifficulty ?? subjects[s].baseDifficulty
    후보 = questions where conceptId=concept, status='verified', difficulty=target
         제외: 최근 30일 내 본 문항 [제안]
         제외: 최근 본 문항과 같은 variantGroupId (같은 날)
    후보 없음 → difficulty ±1 로 완화 → 그래도 없으면 같은 단원 다른 개념
             → aiJobs 에 generate 요청 적재 (동기 대기하지 않음)
    후보 중 calibratedDifficulty 가 target 에 가장 가까운 문항, 동률이면 노출 수 적은 문항
```

- 중복 방지: 최근 출제 이력·유사 문항 그룹 확인, 같은 개념의 다른 문항 우선 `[명세]`

### 2.3 복습 문항 선택

```
due = reviewQueue where dueDate ≤ 오늘
priority = 0.5 × weakness + 0.3 × overdueScore + 0.2 × examScore   [제안 가중치]
  weakness     = conceptMastery.weakness (0~1)
  overdueScore = min(1, 지난 일수 / 7)
  examScore    = 시험일까지 14일 이내이고 examRange 에 포함되면 1 - (남은일수/14), 아니면 0
상위 N개(복습 슬롯 수) 선택, 나머지 이월
각 항목 → 같은 개념의 동형·변형 문항 우선, sourceQuestionId 와 다른 문항 [명세]
          후보가 없으면 원문항 재사용 허용 (해설 재확인 목적)
```

- 우선순위 기준: 취약도·마감일·시험 임박도 `[명세]`

### 2.4 배정 순서

과목별로 묶어 `신규 → 복습` 순으로 보여주되, 학생이 과목 순서를 고를 수 있게 합니다. `[제안]`

## 3. 자기평가 3단계와 간격 반복

### 3.1 입력

| 값 | 라벨 |
|---|---|
| `known` | ① 완전히 알았다 |
| `unsure` | ② 알쏭달쏭하다 |
| `unknown` | ③ 전혀 모르겠다 |

### 3.2 정규 모드 규칙 `nextReview(state, result, config)`

| 상황 | 다음 간격 | 추가 동작 | 근거 |
|---|---|---|---|
| known + 정답 (최초) | 21일 | — | 간격 늘림 `[명세]`, 21일 `[제안]` |
| known + 정답 (복습 성공) | 이전 간격 × 2.0 (최대 60일) | 복습 성공 연속 +1 | `[제안]` |
| known + 오답 | 3일 | `misconceptionFlag = true`, 해설 강조, 오개념 점검 우선 | 오개념 점검 우선 `[명세]`, 3일 `[제안]` |
| unsure (최초) | **14일** | — | `[명세]` |
| unsure + 복습에서 다시 unsure 또는 오답 | 이전 간격 × 0.5 (최소 3일) | | 간격 단축 `[명세]`, 배율 `[제안]` |
| unsure → 복습에서 known + 정답 | known 규칙 적용 | | |
| unknown (최초) | **7일** | | `[명세]` |
| unknown → 복습에서 재오답 | 3일 | 선수개념 문항 2개 다음 배정에 추가 | 더 짧게 + 선수개념 `[명세]`, 수치 `[제안]` |
| unknown → 복습에서 정답 | unsure 규칙(14일)으로 승격 | | `[제안]` |

### 3.3 보정 요소

명세서는 실제 정답, 풀이시간, 이전 복습 성공 횟수, 자기평가를 조합해 간격을 조정하라고 합니다 `[명세]`. 초기 보정식 `[제안]`:

```
interval = baseInterval(위 표)
if 정답 && elapsedSec > expectedSec × 2 : interval × 0.8   # 느리게 맞힘 = 덜 숙련
if reviewSuccessStreak ≥ 3              : interval × 1.2
interval = clamp(round(interval), minDays=1, maxDays=60)
```

### 3.4 weakness 계산 `[제안]`

```
weakness = 0.5 × (1 - 최근10회 정답률)
         + 0.3 × (최근10회 중 unknown/unsure 비율)
         + 0.2 × (misconceptionFlag ? 1 : 0)
```

### 3.5 서비스 표현 주의

"강화학습"이라는 서비스 표현은 쓸 수 있으나, 구현은 **간격 반복(spaced repetition)과 적응형 출제**이며 AI 모델을 강화학습시키지 않습니다 `[명세]`. 약관·마케팅 문구 검수 시 이 점을 확인합니다.

## 3.6 솔직함 보상 (정직 포인트) — 핵심 동기 설계

### 3.6.1 왜 필요한가

간격 반복은 학생이 **모르는 것을 모른다고 표시해야** 작동합니다. 의지가 낮은 학생은 복습을 피하려고 모든 문항에 "완전히 알았다"를 고르기 쉽습니다. 그래서 이 서비스는 **"알쏭달쏭하다"·"전혀 모르겠다"를 고른 행동 자체를 칭찬하고 포인트를 줍니다.**

설계 원칙:

1. **솔직함 포인트는 정답 여부와 무관합니다.** 자기평가는 정답 공개 전에 고르므로(문서 01 §5), 결과를 보고 답을 바꿀 이유가 없습니다.
2. **포인트 때문에 일부러 "모르겠다"를 골라도 괜찮습니다.** 그 개념은 복습 대기열에 들어가고 실제로 다시 풀게 되므로 학습 효과는 그대로 생깁니다. 이 구조는 의도된 것입니다.
3. **가장 큰 보상은 "극복"에 둡니다.** 표시만 하고 끝내는 것보다, 복습에서 다시 풀어 맞혔을 때 더 많은 포인트를 받습니다. 결국 포인트를 많이 모으려면 복습을 해야 합니다.
4. **"알았다"고 했다가 틀려도 벌점은 없습니다.** 대신 "지금 발견해서 다행"이라는 격려와 함께 복습을 배정합니다. 벌점이 있으면 학생이 자기평가 자체를 피하게 됩니다.

### 3.6.2 포인트 규칙 `[제안 수치 — appConfig.rewards 에서 조정]`

| 행동 | 포인트 | 화면 메시지 성격 |
|---|---|---|
| ③ 전혀 모르겠다 선택 | **+3** | "솔직하게 말해줘서 멋져요! 이제 확실히 알게 될 거예요" |
| ② 알쏭달쏭하다 선택 | **+2** | "헷갈리는 걸 알아챈 것도 실력이에요" |
| ① 완전히 알았다 + 정답 | +1 | "정확해요!" |
| ① 완전히 알았다 + 오답 | 0 (벌점 없음) | "괜찮아요, 지금 발견해서 다행이에요. 곧 다시 만나요" |
| **극복 보너스**: ②·③으로 표시했던 개념을 복습에서 정답 | **+5** | "어제 모르던 걸 해냈어요!" |
| **완전 정복**: 같은 개념 복습 2회 연속 정답 | +3 추가 + 개념 정복 배지 | |
| 오늘의 복습 전부 완료 | +5 | |

### 3.6.3 최소 남용 방지 `[제안]`

학습 효과가 생기는 범위의 "포인트 노리기"는 허용하고, **풀지 않고 누르기만 하는 행동**만 막습니다.

- 답안을 입력하지 않았거나 풀이 시간이 3초 미만이면 솔직함 포인트 미지급 (복습 배정은 정상 진행)
- 같은 개념의 솔직함 포인트는 하루 1회 (복습에서 같은 개념에 다시 "모르겠다"를 반복해도 포인트는 하루 한 번)
- 별도 일일 상한은 두지 않음 — 하루 최대 100문제 규칙이 자연 상한 역할

### 3.6.4 학습 엔진과의 관계

- 솔직함 포인트는 **복습 일정·난이도 계산에 영향을 주지 않습니다.** 포인트는 동기부여 계층, 간격 반복은 학습 계층으로 분리합니다.
- 일부러 "알쏭달쏭"을 반복해도 결과는 "복습이 늘어난다"뿐이며, 복습 문항은 하루 최대 100문제 안에서 우선순위대로 처리되고 남은 건 이월됩니다.
- 난이도 자동 조절에서 자기평가가 난이도 **상승을 막지 않도록** 했습니다 (§5.2). 정직하게 "알쏭달쏭"을 골랐다고 계속 쉬운 문제만 받는 일이 없어야 하기 때문입니다.

### 3.6.5 포인트 사용처 ⚠️ 확정 필요

현재 가정: 캐릭터·테마·배경·배지 해금 (문서 07 §3). 현금성 보상이나 결제 할인과 연결하지 않습니다 (미성년자 대상, 남용 유인 확대 우려).

## 4. 7일 무료 체험 모드

체험 기간에는 정규 7일/14일 대신 압축 간격을 씁니다 `[명세]`.

| 일차 | 구성 `[명세]` | 엔진 동작 |
|---|---|---|
| 1 | 교과서·진도·난이도 설정, 초기 학습, 최초 오답노트 | 진단(선택) + 신규 50 |
| 2 | 신규 + 1일차 "모르겠다" 개념 조기 복습 | 1일차 unknown 개념을 2일차에 복습 (⚠️ 아래 참고) |
| 3 | 신규 + 재오답·헷갈림 개념 복습, 첫 변화 추적 | unsure → 2일 간격 |
| 4~5 | 신규 + 2~3일 간격 복습, 재점검, 난이도 미세 조정 | 3일 간격 항목 도래 |
| 6 | 신규 + 취약 단원 집중 복습, 주간 평가 범위 확정 | weakness 상위 단원 가중 |
| 7 | 주간 종합 미니시험 + 자동 채점 + 오답노트 갱신 + 복습 효과 분석 + 학부모 리포트 | 신규 대신 시험 문항, 리포트 생성 트리거 |

> ⚠️ 명세서 표기 불일치: 2일차에 1일차 "모르겠다" 개념을 복습하면 간격은 **1일**인데, 표에는 "체험용 2일 간격"으로 적혀 있습니다. "2일차에 복습"과 "2일 간격" 중 무엇을 의도했는지 확정이 필요합니다. 이 문서의 기본값은 **2일차에 복습(간격 1일)** 로 둡니다.

`trialSrs` 설정 `[제안]`:

```json
{ "unknown": 1, "unsure": 2, "known_wrong": 1, "known_correct": 4, "unknown_wrong_again": 1 }
```

- 체험에서도 신규 50, 최대 100 원칙 적용 `[명세]`
- 체험 종료 후 `mode = 'regular'`로 전환, 기존 로그·예약 복습은 유지 `[명세]`. 단, 체험 중 예약된 항목의 `dueDate`는 그대로 두고 **이후 계산부터** 정규 간격 적용 `[제안]`
- 7일차 이후 결제하지 않으면 `access = 'expired'` → 새 문제 배정 중단 `[명세]`

## 5. 개인별 난이도 조절 `adjustDifficulty()`

### 5.1 초기 난이도

- 학생·학부모 직접 설정 또는 간단한 진단 문제 `[명세]`
- 진단 `[제안]`: 과목당 난이도 2·3·4 각 2문항 → 정답 수로 2~4 결정

### 5.2 자동 조절 (개념 단위, `autoDifficulty = true`일 때만)

| 조건 `[제안]` | 동작 |
|---|---|
| 최근 해당 개념 5회 이상, 정답률 ≥ 80%, 평균 시간 ≤ 예상시간 | +1 |
| 최근 5회 이상, 정답률 ≤ 40% | −1 |
| 그 외 | 유지 |

> 자기평가는 난이도 판정에 쓰지 않습니다. "알쏭달쏭·모르겠다"를 고른 학생이 그 때문에 쉬운 문제만 받으면 솔직하게 표시할 이유가 줄어듭니다 (§3.6). 자기평가는 복습 일정과 취약도(weakness)에만 반영합니다.

안전장치 `[명세]`:

- **급변 방지:** 한 번에 한 단계, 같은 개념은 3일에 1회만 변경 `[제안: 3일]`
- **학년 범위 초과 방지:** 1~5 범위, 학년별 상한·하한은 `appConfig.difficulty.gradeBounds`
- **자동조절 끄기 옵션:** `autoDifficulty = false`면 `baseDifficulty` 고정
- AI는 장기 패턴 요약에만 필요 시 참여 `[명세]`

## 6. 오답노트

- 자동 분류: 과목 → 단원 → 개념 `[명세]`
- 오답 원인: 개념 미이해 / 계산 실수 / 문제 해석 / 기타 — 학생 선택 또는 AI 추정, **AI 추정은 화면에 "추정" 배지 표시** `[명세]`
- 오답노트에서 "다시 풀기" 시 변형 문항 제공, 결과는 복습으로 기록

## 7. 학생 화면 데이터

오늘의 학습량, 연속 학습일, 취약 개념, 오답노트, 예정 복습 `[명세]`. 학습 성향 분석은 관측 가능한 패턴(예: "오후 학습 시 정답률이 높음")에 한정하고 성격·지능을 단정하지 않습니다 `[명세]`.

## 8. 테스트 요구사항

`packages/core`는 아래 시나리오의 단위 테스트를 필수로 둡니다.

- 신규 50 + 복습 70 → 총 100, 복습 20 이월
- 복습 문항이 원문항과 다른 변형 문항으로 선택됨
- known + 오답 → misconceptionFlag, 3일
- 난이도 3일 쿨다운, 범위 클램프
- 체험 → 정규 전환 시 예약 유지
- KST 자정 경계 날짜 키 계산
- 솔직함 포인트: unknown +3 / unsure +2 가 정답 여부와 무관하게 지급
- 극복 보너스: unsure/unknown 표시 개념의 복습 정답 시 +5
- 3초 미만·빈 답안은 솔직함 포인트 미지급, 복습은 정상 배정
- 같은 개념 솔직함 포인트 하루 1회
- 포인트가 복습 간격·난이도 계산 결과에 영향을 주지 않음
