# 노학원 · 교재 기반 맞춤 학습

B 캐릭터 퀘스트 디자인으로 구현한 Next.js + Firebase 학습 앱입니다. 로그인 사용자의 교재·문항·답안·포인트·복습 일정은 Firestore에 저장하며, 채점과 권한 확인은 서버에서 수행합니다.

## 실행

```sh
npm install
# apps/web/.env.example을 apps/web/.env.local로 복사한 뒤 서비스 키 설정
npm run dev
```

Node.js 22 이상. 학습 화면: http://127.0.0.1:3000/b · 관리자: http://127.0.0.1:3000/admin

## 교재에서 학습까지

1. **나의 교재**에서 공식 목차 교재를 선택하거나 사진·PDF·TXT·텍스트를 올립니다.
2. AI가 읽은 제목·학년·과목·목차·본문을 직접 확인하고 수정합니다. 제목·목차가 비슷한 기존 교재도 추천합니다.
3. 현재 시작 단원과 종료 단원을 선택합니다. 목차만 올렸다면 출제할 단원의 본문·학습 노트도 추가합니다.
4. 단원별 출제를 누르면 문제 생성과 독립 풀이 검증이 진행됩니다. 학습 시작 시 은행이 부족하면 출제를 자동 요청합니다. 검증에 실패하거나 유사한 문항은 검수 대기로 남습니다.
5. 승인된 객관식·단답형을 풀고 이해도를 선택하면 서버가 채점하고 포인트·복습 일정을 저장합니다. 기본 과목별 하루 10문제, 복습 포함 총 100문제 상한을 적용합니다.
6. 오답노트, 재풀이, 주간/범위 평가, 주간 리포트로 이어집니다. 단원 내 개념별 최소 신규 문항 수를 채우면 선택 범위의 다음 단원으로 이동합니다.

교과서 본문을 자동 수집하지 않습니다. 공식 목차와 사용자가 확인한 본문을 구분합니다. 공개 교재 목록은 비상교육 2022 개정 중1 대단원 목차 5종과 자체 기초 점검 자료 5종이며, 모든 출판사·판본을 포괄하지 않습니다. 국어는 1-1, 사회 ①은 학교 편성에 따라 학년을 선택합니다.

## 구현한 기능

- Google 로그인, 서버 세션, 보호자별 최대 5개 학습 프로필
- 학생 Google 계정 초대: 이메일 지정 → 코드 입력 → 보호자 승인; 결제·보호자 관리 권한 분리
- 자료 인식, 목차 편집·재정렬, 교재 매칭 추천, 학습 범위, 개념·성취기준 메타데이터
- 비동기 AI 출제/검증, 토큰 사용량, 계정별 AI 한도, 작업 재시도와 복구
- 서버 채점, 중복 제출 방지, 과목별/전체 한도, 포인트 원장, 복습·난이도 조절
- 오답 메모·북마크·오류 신고, 학습자별 통계, 주간 리포트 저장/인쇄
- 다크·라이트·시스템 테마, 한국어/영어/일본어/중국어 UI, 저자극 모드
- 관리자 역할, 교재·개념·문항 검수, 신고 처리, 학습자/결제 조회, 설정 변경 이력
- 데이터 JSON 내보내기, 재인증 후 삭제 또는 결제 이력 보존 검토 요청
- 7일 체험 및 Toss 정기결제 연동 코드, 중복 승인 방지, 웹훅 재조회, 자동 갱신·해지 예약

로그인 없는 `/b`와 기존 A 시안 `/a`는 고정 문항을 사용하는 브라우저 체험입니다. 실제 교재 학습을 테스트하려면 로그인한 `/b`를 사용하세요. 체험 기록을 실제 학습 기록에 자동 합치지 않습니다.

## AI와 비용

기본 모델은 `gpt-6-luna`입니다. 인식·생성과 별도의 정답 없는 검증 요청에 사용하고, 일반 채점과 통계에는 AI를 쓰지 않습니다. `AI_MODEL` / `AI_VERIFY_MODEL`로 변경할 수 있습니다.

2026-10-14 공식 기본 단가: 입력 $0.10 / 출력 $0.50, 100만 토큰 기준. 8문항 생성+검증 실측 1,809 입력 / 2,022 출력 토큰, 추정 $0.0011919. 이미지·PDF 인식 비용은 별도이며 실제 청구액은 공급자 기록을 따릅니다. [공식 모델 안내](https://developers.openai.com/api/docs/models/gpt-6-luna)

자료는 OpenAI API로 전송되며 `store: false`를 지정합니다. 이 옵션은 공급자의 별도 데이터 보관 정책을 대체하지 않습니다. 원본 업로드 파일은 메모리에서 처리하고 앱 저장소에 보관하지 않습니다.

## 검증

```sh
npm test
npm run typecheck
npm run build
# 선택: 연결한 Firebase와 OpenAI를 사용하는 유료 통합 검증
node scripts/verify-integrations.cjs --live
```

단위 테스트 32개, 실제 서비스 통합 점검 16개 통과. 통합 검증은 자체 작성 수학 자료와 임시 프로필만 사용하며 종료 시 임시 데이터를 정리합니다. 결제 관련 테스트는 상태 처리 검증이며 결제사 실승인이 아닙니다.

실제 Chrome에서 Google 로그인, 업로드 이미지 인식, 출제, 풀이, 오답 저장, 소유자 관리자 접근을 확인했습니다. PDF 인식도 실제 API로 확인했습니다. 테스트 방법과 제한은 [현재 구현·테스트 안내](docs/13-implementation-testing.md)를 참고하세요.

## 연결과 운영

Firebase Admin 키와 OpenAI 키는 서버 전용 `.env.local` / 호스팅 환경 변수에 넣습니다. 프런트 번들에 포함하지 않습니다. Firestore 직접 접근 규칙은 차단 상태를 유지합니다. 최초 소유자 설정은 운영자가 `node scripts/set-owner.cjs <email>`로 수행합니다.

토스페이먼츠 테스트 키가 없어 카드 등록·실제 결제 승인은 아직 확인하지 않았습니다. 사용자는 학습 기능부터 테스트하기로 선택했습니다. 실결제는 기본 차단되며 별도 환경 설정이 필요합니다.

`/api/cron`은 `Authorization: Bearer <CRON_SECRET>`이 필요합니다. 배포 시 `apps/web/vercel.json`의 하루 한 번 작업으로 중단된 출제·주간 리포트·만기 갱신을 처리합니다. 한 번에 학습자 30명, 출제 복구/결제 각각 최대 3건으로 제한하며 커서를 저장합니다. 사용자 수가 커지면 더 잦은 스케줄과 전용 작업 큐로 확장해야 합니다. 로컬에서는 관리자에서 수동 실행할 수 있습니다.

현재 변경은 로컬에서 실행·검증했습니다. 호스팅 배포와 운영용 결제·법적 고지 확정은 별도 단계입니다. 관리자 삭제 요청 메모는 삭제 처리를 대신하지 않습니다. 결제 기록이 있는 계정의 실제 삭제·환불은 운영자가 보존 범위를 검토해 처리해야 합니다.

`docs/01`~`docs/10`은 최초 설계안이며 향후 운영 확장 항목도 포함합니다. 구현 현황 판단은 이 README와 문서 13을 우선합니다.
